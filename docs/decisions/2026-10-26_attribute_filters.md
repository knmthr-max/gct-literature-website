# 属性による絞り込み(臨床論文)

決定日: 2026-10-26(画面案は 2026-10-25 に承認)

## 決めたこと
- AIが抄録から抽出した属性を、公開サイトの各論文エントリの `attrs` に入れ、臨床論文を属性で絞り込めるようにする。
- 絞り込みは臨床のときだけ出す(区分=臨床)。同じ項目の中は「いずれか」、項目をまたぐと「すべて」。
- 共通の項目(症例報告を含む全デザインで同じ選択肢): 臨床テーマ、原発部位、組織型、性別、年齢区分、治療。
- 研究デザインを選んだときだけ出す固有の項目: RCT・非ランダム化試験(治療ライン・主要評価項目・相)、SR・MA(統合の対象・定量的統合)、観察研究(研究の型)。
- 病期・IGCCCG・例数は、絞り込みの項目にせず、カードに表示する。結果の数値(生存率・ハザード比など)は抽出も表示もしない。
- 「不明」「記載なし」「その他」は選択肢に出さない。抄録に書かれていない論文は、その項目を選ぶと除かれる(画面に注記)。
- 妊娠性絨毛癌は、組織型の独立した選択肢にする(2026-10-26 指示)。

## 仕組み
- 抽出: `scripts/extract_attributes.py`(RCT・非ランダム化試験・SR・MA・観察研究の属性と、臨床の全論文の臨床テーマ)、`scripts/extract_case_attributes.py`(症例報告の共通項目)。結果はデータ側 `processed/attributes_v2/` と `processed/case_attributes/`。
- 取り込み: `scripts/sync_site_attributes.py`(dry-run が既定)で `data/papers/` の `attrs` に入れる。デザイン固有の項目は、今のタグと抽出時のデザインが同じときだけ入れる(タグを直した論文に古い項目が残らない)。
- 配信: `scripts/build_site_search.mjs` が `attrs` を `search/list.json` に含める(+約2MB、gzip後 約+2MB)。
- 画面: `assets/app.js`、項目と表示名は `assets/attr-labels.js`。URLは `?kubun=clinical&design=RCT&f_si=testis,ovary` の形で、結果を人に渡せる。
- 確認: `npm run check:attr`(実ブラウザで、件数・AND/OR・URL再現・固有項目・英語ページを確認)。

## 妊娠性絨毛癌を後で一覧から外したくなったとき
- 選択肢だけ消す: `assets/attr-labels.js` の `gestational_choriocarcinoma` の行を削除する(論文は残る)。
- 論文ごと消す: 対象の論文を DB で `excluded` にして公開データ(`relevance_status`)に反映する。属性の抽出結果(`histology` に `gestational_choriocarcinoma`)で対象の論文を特定できる(観察研究 339 件、SR・MA 8 件ほか。2026-10-25 時点)。

## 既知の限界
- 抄録に書かれていない属性は取れない(年齢区分の約7割、病期の大半が不明)。
- SR・MAの組織型は、抄録に名前のあるものだけ。
- AIの抽出には揺れがある(同じ入力でも、組織型や臨床テーマが変わることがある)。パイロット40件を目視で確認して採用した。
- 属性の抽出元は症例報告と他のデザインで、プロンプトの版が違う(症例報告は v1、他は 2026-10-24 に直した版)。共通の選択肢は同じで、症例報告側の選択肢は上位互換に拡張済み。
